## 容量与长时运行

按第一轮 Bag 41.34 MiB/s，30、35 分钟分别约 **72.67、84.78 GiB**。按整个移动阶段数据卷消耗 42.06 MiB/s，分别约 **73.93、86.26 GiB**。正式启动门槛 110 GiB。现场脚本另算规划上限，给地图收尾、日志和文件系统留 25 GiB，并将实测速率上浮 10%。以本次余量计算，`(201.31−25)×1024/(42.06×1.10×60) ≈ 65.0 分钟`。这是容量预算，供电、温度、实时性和现场路线另行约束。脚本不设置 30 分钟计时停止。

## 监测字段与实际验证

每个正式 FIELD 根目录保存 `resources_2s.jsonl`、`journal.jsonl`、`events.jsonl`、版本预检及工具摘要。内层 RUN 继续由 B1 保存 processing.csv、visual_lru.csv、输入计数、传感器诊断、重力事件和地图。采样器以 nice 10 运行，只读 procfs、sysfs、B1 已写出的小型状态文件及 NVMe SMART。没有新增 ROS 传感器订阅者。

| 字段 | 单位、口径和节拍 |
|---|---|
| wall_ns、mono_ns、boot_id、interval_s | UNIX 墙钟 ns、Linux CLOCK_MONOTONIC ns、启动周期、相邻采样秒数。事件同时记录写入双时钟；手机补录另存带时区的事件墙钟，事件单调时间为空。 |
| cpu、loadavg | 每约 2 s 用 /proc/stat 差分。全机与各核 busy_pct 排除 idle 与 iowait，iowait_pct 单列，分母为各自总 tick；首样本无差分。loadavg 为 1/5/15 分钟平均负载。 |
| policy_kHz、thermal_mC | 每约 2 s 记录 policy 核列表、cpuinfo_cur_freq 实读、scaling_cur_freq 和 scaling_max_freq，单位 kHz。七个有效温区读数单位毫摄氏度。热节流判断需结合内核、温区阈值、策略上限与负载变化。 |
| memory_KiB、processes | 系统总量、可用、缓存/缓冲、Dirty/Writeback、Swap 总/空闲，单位 KiB。算法、相机、驱动、录包、归档及采样器逐 PID 记录 start_ticks、线程数、CPU tick、CPU%、VmRSS 与 VmHWM（KiB）。进程 CPU 以单核 100% 计，多线程可超 100%。约 20 s 读取 smaps_rollup 的 Pss（KiB）。进程创建前/退出后字段缺席。 |
| nvme、disk_free_bytes、smart | 整个 nvme0n1 的扇区写入差分 MiB/s、忙时间 util_pct、/data 可用字节。约 40 s 保存 SMART，当前 nvme-cli 的 JSON 温度为 K，305 K 约 32 °C。avail_spare、percent_used 为百分数，计数和告警保留原单位。 |
| net、journal | 每约 2 s 记录雷达专网和 WLAN carrier、operstate、累计 RX error/drop。会话 journal 包含当前 boot 启动监测前一分钟及后续内核、NetworkManager、chrony、udev、OOM 服务和监测启动标记。journal 的 __REALTIME_TIMESTAMP、__MONOTONIC_TIMESTAMP 为 µs，_BOOT_ID 区分启动周期。采样数据逐行 flush，约每 10 s 同步资源和 journal 文件，正常结束再同步。异常掉电可能损失末批。 |
| archive_counts | 从 B1 的 map/status.json 读取同一版本的几何、彩色累计点数、位姿计数、重力和 TF 状态，保留状态文件写入时刻供估计陈旧程度。计数对应归档器的追加顺序；状态文件 mtime 不作传感器采集时刻。 |

实际低负载验证运行 104.56 s，写入 52 行、87,947 B。间隔中位数 2.0105 s、最大 2.0109 s，8 核、3 个频率策略、7 个温区、6 次 PSS、3 次 SMART 均有数据，真实 journal 启动标记落在 NVMe。采样器自身平均占用单核 1.36%，最大 1.99%，峰值 RSS 11.31 MiB；该统计未合并 journalctl 与短时 SMART 子进程。现场带载影响以 B1 原生 processing/cycle 与首轮同阶段指标核实。

板端隔离验证使用真实 tmux、正式外围监测和事件代码，采集、录包和地图验收端点使用替身。修正 procfs Boot ID 用文件长度快速比较产生的误报后，已验证退出启动 SSH 后继续运行、重新连接、标记、正常收尾。最终 34 行中取得替身算法/录包进程 31/32 组数据，各 3 次 PSS，读取历史地图计数样例 33 组。两项作业退出码及收尾状态均为 0。成品核验另用第一轮真实数据只读验证。传感器未接时，正式预检阻止创建实验目录。正式 30 分钟带载和量测结果待现场采集。

## 精度、性能与异常分析依据

| 后续问题 | 本轮留下的证据及分析边界 |
|---|---|
| 起终闭合、水平与垂直漂移 | 由重力对齐 TUM 对实际 P0 初末静止窗求位置质心、平均姿态，报告水平差、带符号 Δz、三维差和相对旋转角，并列 P0 复位误差。对独立量测的检查点按累计路程报告分段残差与返访差。无外部高程/位置约束区段只能报告估计变化，沿途连续真实漂移仍缺真值。 |
| 静止定位、尺寸、局部平面 | 分窗报告位置/姿态 RMS、P95、最大值。按照片、墙距端点、测量高度和方位，在同一 map_gravity 截面拟合地面及左右墙，报告样本/内点、阈值、法向、残差及量具重复性。地图长度减外测长度才用于尺寸误差。 |
| 重访一致性、重影 | 对同一区域在相同 ROI 中按归档累计点数切片，分别保留当次估计坐标，报告点到同一参考平面的带符号距离、层间距与分布。B1 归档器按接收顺序追加全量点，单次重力旋转保序。使用已进入重力坐标、计数单调的样本，核对末次计数与 PCD 头。采样约 2 s，状态约 1 s 刷新；边界选相邻稳定窗、报告其不确定性。最终 PCD 缺逐点采集时刻。更细边界可在实验后用整包连续离线回放及分段导出器，核对回放时轴与初始化差异。不对两次经过追加 ICP 配准。 |

| 相机、IMU、供电与故障 | 结束后从七路 Bag 重算消息头及接收间隔、重复/跳变、逐片统计。对照相机取帧/SDK、时钟 latch、Line0/曝光事件、timeshare 写/读和雷达诊断。frames.csv 继承首轮布局，按实际列数和 metadata 对照。与 journal、资源曲线交叉定位 USB reset、CMA、雷达载波、PCIe/NVMe、ext4、OOM、温控、进程退出/重启。TUM 在 LIVO 中采用发布墙钟，state_s 在传感器轴，processing.wall_s 在主机单调轴。借同期双时钟样本分段关联，时钟 step 前后单独处理。标称 5 V/3 A 为电源额定值；板端缺少经校验的输入端电压/电流，电气余量与绝对曝光同步精度仍需独立测量。 |
