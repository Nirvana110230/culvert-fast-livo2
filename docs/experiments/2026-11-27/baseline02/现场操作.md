# Baseline 02 走廊实验现场操作

适用板端为 Orange Pi 5 Ultra，B1 标签为 `stage-b1-20261127`。实验员决定路线、时长和停止时间。设备与量具就绪、现场人员明确同意开始后执行启动段。命令中的 `FIELD` 始终指本轮外层目录，`RUN` 指 B1 在其中生成的内层目录。

## 1. 接线、量测与无线登录

按第一轮接法给主控独立供电，给雷达和同步器经 DP100 供电。固定支架，接雷达专网、相机 USB Host 和 Line0 触发线。标记 P0 轮位、车头方向和传感器参考点，拍下复位方式。在可重复辨认的断面标出 P01、P02，记下墙距、走廊宽度、沿线距离、地面或门槛高差的实际测量值。建议记录两次读数，保留量具分辨率、测量端点、高度和照片方向。手机时间与板端墙钟对照一次，记差值和时区。现场安排能够停车并操作正常停止的人员。

Windows 与板端都连入手机热点后，先经 USB 读板端当前无线地址，再从 Windows 经该地址登录。以下为 PowerShell。设备树历史字符串为 `RK3588 OPi 5 Max`。

```powershell
ssh -o StrictHostKeyChecking=yes opiss-usb 'hostname && id -un && uname -m && cat /proc/sys/kernel/random/boot_id && ip -br -4 addr show dev wlan0 && nmcli -g GENERAL.CONNECTION dev show wlan0'
$wifiAddress = Read-Host '输入刚核实的板端热点 IPv4'
ssh -4 -o BatchMode=yes -o StrictHostKeyChecking=yes -o HostKeyAlgorithms=ssh-ed25519 -o HostKeyAlias=10.77.77.2 -o ConnectTimeout=6 "orangepi@$wifiAddress"
```

板端 Bash 执行下列命令。核对同一 Boot ID、`orangepi / orangepi5ultra / aarch64`、时间与实际日期。需要重新上电时，重新检查同步及热点地址。

```bash
cd /home/orangepi/baseline02
hostname && id -un && uname -m
cat /proc/sys/kernel/random/boot_id
date -Is && timedatectl && chronyc tracking
./field.sh preflight
```

`ready: true` 要求正式 ELF、配置与发布身份一致，管线空闲，NVMe 可写且可用至少 110 GiB，时间已同步，相机已枚举，雷达走指定专网且纯查询回读 Idle 2。这个阶段可验证接线和时间；实际 IMU、触发及视觉更新在本轮静止初始化时确认。同步器的独立工作状态须结合 Line0、相机事件、图像与融合计数判断。

## 2. 在 P0 启动唯一会话

保持静止。在板端 Bash 执行并保存输出的完整 `FIELD`。现场未确认时停在上一步。

```bash
cd /home/orangepi/baseline02
FIELD=$(./field.sh start) && printf '%s\n' "$FIELD"
./field.sh status "$FIELD"
./field.sh ready "$FIELD"
```

板端在 `/data/robot/maps/fast_livo2/runs/corridor_baseline02_<UTC>_<随机串>/` 建档。tmux 先启动低优先级监测及 journal，确认落盘后单独启动 rosbag2，确认监听后调用正式 `start.sh --runs-dir "$FIELD"`。ROS 2 Humble 使用线上域 215、仅本机通信。Bag 为 SQLite3、536870912 B 分片、100 ms 发现轮询，完整录制 LiDAR、IMU、Image、CameraInfo、camera_metadata、camera_events、camera_clock 七路原始消息。

刚启动时 `ready` 可暂时为假。在 P0 静止约 3 分钟，等待 `ready: true` 再移动。它检查当前会话的 ELF、解析配置和参数回读、重力和 TF、两次相隔 3 秒的三路输入/成功同步/视觉更新/位姿/Bag 大小增长、五类真实进程及监测新鲜度。还会只读最近已关闭的分片，确认七路各有实际消息。用 `status` 确认 map、bag、mon 三个独立 tmux 作业活动。热点 SSH 成功且供电独立后，只拔 Windows USB 维护线。无线失联期间继续原定路线并用手机记时。

## 3. 状态与事件

重连后先恢复变量，核对状态中的 FIELD、内层 run 与 Boot ID。状态入口也会显示正式管线最近一轮，在当前 run 与 FIELD 匹配后解释计数。

```bash
cd /home/orangepi/baseline02
read -r -p '粘贴本轮 FIELD 完整路径 ' FIELD
./field.sh status "$FIELD"
./field.sh event "$FIELD" MOVE_START
./field.sh event "$FIELD" CHECKPOINT_P01 --note '填写实际地标、方向、停留情况'
```

按实际过点写入 `CHECKPOINT_P02`、`NEW_AREA_START`、`REVISIT_START`、`LIFT_START`、`LIFT_END`、`RETURN_P0` 和 `MOVE_END`。重复经过同一地标可重复记录，并在备注标明第几次、行进方向。起止边界 `SESSION_START`、`SESSION_END` 由板端自动记录。推荐时段依次为 0–3 分钟静止、3–9 分钟旧区域、9–21 分钟扩展、21–27 分钟重访、27–30 分钟 P0 复位静止；分析使用实际标记。

手机补记允许在收尾后追加。以下命令读取手机上的**实际日期时间及偏移**，可保留到微秒。补录时间、写入时板端时间及两者来源各自保存。手机读数精度和估计偏差写入备注。事件补完后再导出和计算最终文件校验值。

```bash
read -r -p '手机实际事件时间，格式 YYYY-MM-DDTHH:MM:SS+08:00 ' AT
./field.sh event "$FIELD" CHECKPOINT_P02 --at "$AT" --note '手机补录，填写地标、方向和估计时间误差'
```

## 4. P0 正常停止与完整性核验

精确复位 P0，分别记返回时刻与实际停稳时刻，保留结束静止窗，再执行停止。

```bash
cd /home/orangepi/baseline02
./field.sh event "$FIELD" RETURN_P0
./field.sh event "$FIELD" MOVE_END
# 完成计划的结束静止窗后
./field.sh stop "$FIELD"
./field.sh status "$FIELD"
```

stop 把请求交给本轮板端作业。正式 `stop.sh` 等算法和地图写完。随后给本轮录包发 Ctrl+C，等元数据关闭，再停止监测、写入结束事件并核验成品。USB 或热点重连后仍可查询。归档时间随地图大小增长。等待 `final.status` 出现，保持供电。

```bash
while [ ! -f "$FIELD/final.status" ]; do
  tmux -L fast-livo2-field has-session -t "=b02_map_${FIELD##*/}" 2>/dev/null || break
  sleep 3
done
cat "$FIELD/final.status" "$FIELD/monitor.exit" "$FIELD/recorder.exit"
cat "$FIELD/integrity.json" "$FIELD/map_check.log" "$FIELD/bag_info.log"
RUN=$(find "$FIELD" -mindepth 1 -maxdepth 1 -type d -name '????????T??????Z_*')
cat "$RUN/sensors/session.json" "$RUN/map/result.json"
/home/orangepi/fast_livo2/status.sh --json

```

正常结果为 `final.status=0`、`integrity.json` 中 `pass_all=true`、正式状态 complete 且 inactive，本轮作业均结束。日志保留各拥有进程的退出码、是否强制结束、相机恢复，以及雷达 Idle 的 ACK、回读和两秒零点云/IMU。核验包含七路总数和逐片表计数对元数据、两份 PCD 与 TUM 的 SHA256、重力变换与 manifest 身份。需要重新核对时执行 `./field.sh check "$FIELD"`。若作业消失且缺少 final.status，或核验失败，保留整个 FIELD、当前 Boot ID 和错误日志。重启后先对照两个 Boot ID 和持久化的会话末条记录，可能缺少最后一批落盘数据。不要在旧 FIELD 中重新录制。

离线回放从整个 Bag 起点重新初始化。只在正式实验结束后进行。下面使用另一 ROS 域和独立回放输出目录。只检查成品用 `view.sh --check`，不打开 RViz。

## 5. 导出到 Windows

USB 重新连接，确认目标盘容量，使用新的本地目录。完整导出包含 Bag、PCD、TUM、实际配置、日志和现场标记。以下为 PowerShell，目录示例沿用第一轮项目。整轮数据保存在本地。

```powershell
$remoteRound = Read-Host '粘贴已结束的 Baseline 02 FIELD'
if ($remoteRound -cnotmatch '^/data/robot/maps/fast_livo2/runs/corridor_baseline02_[0-9]{8}T[0-9]{6}Z_[A-Za-z0-9]{6}$') { throw 'FIELD 格式不符' }
$winRoot = 'E:\涵洞巡检轮式机器人\orangepi-dev\data\corridor_runs'
$localRound = Join-Path $winRoot ($remoteRound.Split('/')[-1])
if (Test-Path -LiteralPath $localRound) { throw '本地目标已存在' }
New-Item -ItemType Directory -Force $winRoot | Out-Null
scp -o StrictHostKeyChecking=yes -r "opiss-usb:$remoteRound" $winRoot
if ($LASTEXITCODE) { throw '导出未完成' }
$checks = ssh -o StrictHostKeyChecking=yes opiss-usb "set -o pipefail; cd '$remoteRound' && find . -type f -print0 | sort -z | xargs -0 -r sha256sum"
if ($LASTEXITCODE -or !$checks) { throw '板端清单读取失败' }
foreach ($row in $checks) {
    if ($row -notmatch '^([a-f0-9]{64})  \./(.+)$') { throw '清单格式异常' }
    $expected = $Matches[1]
    $file = Join-Path $localRound $Matches[2]
    if ((Get-FileHash -LiteralPath $file -Algorithm SHA256 -ErrorAction Stop).Hash -ne $expected) { throw "SHA256 不匹配 $file" }
}
if (@(Get-ChildItem -LiteralPath $localRound -File -Force -Recurse).Count -ne @($checks).Count) { throw '文件数不符' }
$checks | Set-Content -LiteralPath "$localRound.sha256" -Encoding utf8
```
